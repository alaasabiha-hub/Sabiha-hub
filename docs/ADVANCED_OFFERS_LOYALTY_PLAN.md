# العروض المصورة والولاء المتقدم — طلب المستخدم 14 نوفمبر 2026

## ترتيب التنفيذ المعتمد

أكمل العمل الجاري أولًا؛ لا إعادة بناء للمكتمل ولا تعديل للإنتاج أو نشر. احتفظ بالمعرّفات والفواتير والحقوق القديمة، مع إصدارات ثابتة للشروط وإعدادات المالك فقط. لا تعرض أسعارًا أو عروض اختبار في الإنتاج. لكل مرحلة كود فعلي واختبارات محددة ونقطة استعادة.

1. إغلاق المرحلة الجارية: اختبار AI المتعثر (نجح)، احتساب الزيارات وعكس الاسترداد والتزامن والمعالج المجدول (نجحت)، ثم إعداد قواعد الاستبدال الصريحة للمالك. **الاستبدال الفعلي عبر الحجز والفاتورة لم يكتمل بعد**.
2. العروض المصورة: إعادة استخدام إدارة العروض الحالية ورفع الصور الآمن، لا نظام بديل. عدد العروض ليس مقيدًا تجاريًا؛ واجهات القوائم تحتاج pagination. صور رئيسية ومعرض خدمة وقبل/بعد، نصوص AR/EN، أسعار حقيقية ومكافآت، مواضع home/offers/banner، معاينة موبايل، مسودة/منشور/موقوف/منتهي. تحديث مباشر من Supabase، ضغط وفحص MIME/توقيع الملف/الحجم والأبعاد، وصلاحيات Storage منفصلة للنشر والملفات الخاصة. لا تخلط صور فحص سيارة العميل الخاصة بصور تسويق منشورة دون موافقة صريحة.
3. سياسات الولاء المتقدمة: معدل خدمة/فئة، مضاعفات خدمة/يوم/فترة، مكافآت زيارات ونقاط مطلوبة لكل مكافأة، خدمات وفروع وعملاء مؤهلون، حد فاتورة/خصم وصلاحية واستخدام لكل عميل/إجمالي، إيقاف واستئناف، بعد اكتمال الخدمة والدفع الموثوق فقط، منع التكرار، إلغاء/استرداد صريح، دفتر كامل. **الزيارات الحالية ليست نقاطًا مالية؛ لا استيراد أو تحويل ضمني للدفتر القديم**.
4. تجميع الخصومات: لكل عرض قابلية الجمع مع الكوبون والنقاط والعروض الأخرى، حد إجمالي، ترتيب وفض تعارض وأولوية، ومعاينة سعر على الخادم قبل النشر/الحجز. تحسب التسوية النهائية ذريًا؛ لا تغيير لشروط فاتورة صدرت سابقًا.
5. التحليلات الفعلية وAI للمالك: المشاهدات والعملاء المعروفون والاستخدام والحجوزات والإيراد المنسوب، تكلفة الخصم/المكافأة، عملاء جدد/عائدون والخدمات الجاذبة، توصيات معدلات النقاط. لا تساوِ إشارات المشاهدة من العميل بإثبات عميل فريد؛ افصل المجهولين عن الحسابات المعروفة. لا تنسب حجزًا إلى عرض باستنتاج من السعر/الخدمة؛ يلزم رابط إصدار عرض محفوظ وقت العملية. الربح يحتاج تكاليف فعلية مكتملة؛ لا ادعاء تأثير سببي أو توقع موثوق دون أدلة كافية.

## اختبارات الاعتماد المطلوبة

- العربية RTL والإنجليزية LTR، الكمبيوتر والموبايل، معاينة العرض قبل نشره.
- ملكية الإعدادات وRLS ومنع الوصول/الرفع/التعديل غير المصرح، ومنع نشر ملفات مزيفة أو كبيرة.
- حفظ إصدار شروط العرض عند الحجز؛ تغييرات المالك تؤثر في العمليات المستقبلية فقط.
- سباقات سقف الاستخدام والحجز والخصم والنقاط والاستبدال والاسترداد وإعادة المحاولة.
- فصل رسوم/مدفوعات Sandbox عن التحصيل الحقيقي، وعدم اختلاق تكلفة أو ربح.
- حفظ الأدلة والنتائج السابقة وعدم إعادة الفحوص الناجحة بلا تغيير مؤثر.

## قرار المستخدم الخاص بالاستبدال

اختار المستخدم: **إعدادات صريحة من لوحة المالك** لقواعد التجميع والانتهاء والإلغاء واسترداد الزيارة المؤهلة. يبقى الاستبدال معطلًا حتى اكتمال القواعد والمسار التنفيذي واختبارهما. لا اختيار افتراضي يغيّر حقوق العملاء أو يفرض دينًا ماليًا بأثر رجعي.

## تبعية Walk-in المضافة لاحقًا

تُنفذ الزيارة المباشرة في مرحلة الكاشير والولاء بعد تثبيت مسار الاقتباس/التخصيص/الفاتورة الجاري. تستعمل نفس القواعد والحدود والمراجعة، مع سجل زيارة مباشر مستقل عن حجز التطبيق وموافقة عميل موثقة لمرة واحدة؛ الهاتف للبحث فقط. دعم «عدد النقاط» يعتمد دفتر النقاط المرن ومخطط الخصومات، بينما مكافآت الزيارات تستفيد من التخصيص الحالي. يمكن تنفيذ إدارة الصور المستقلة بالتوازي لاحقًا، دون تعطيل المسار المالي. لا مراجعة بعد كل قسم ولا نشر أو تحصيل حقيقي ضمن التفويض الحالي.

## العملاء بدون تطبيق — إضافة المستخدم، محفوظة دون تعطيل العمل الجاري

- المرحلة المناسبة: أساس هوية العملاء ثم Walk-in والكاشير والولاء، بعد تثبيت مسار حجز المكافأة الجاري. لا إعادة بناء للمكتمل.
- ملف عميل مستقل عن Supabase Auth: الاسم والهاتف الموحد والسيارات والموافقة، مع بحث كاشير محدود الصلاحيات ومنع التكرار والتزامن. لا إنشاء حسابات Auth وهمية ولا تغيير UUID أو مفاتيح العلاقات الحالية.
- الزيارة والفاتورة والدفتر مرتبطان بملف العميل؛ الاحتساب فقط بعد اكتمال الخدمة وتأكيد الدفع. الاستبدال يحتاج إثبات ملكية وموافقة مرتبطة بالعملية؛ الهاتف وحده ليس تفويضًا.
- الربط اللاحق بالتطبيق يحتاج تحقق هاتف موثوقًا ودليلًا حديثًا من الخادم ومسار تعارض/مراجعة، مع حماية تغيير الرقم وإعادة تدويره. لا دمج تلقائي لأشخاص مختلفين ولا كشف سجل عبر البحث بالهاتف. مزود OTP خارجي لم يُجهز بعد؛ يمنع الربط والاستبدال غير الآمن عند غيابه.
- إعدادات المالك تشمل أهلية Walk-in ومعدلات الخدمات والمراجعة وتقارير العملاء المرتبطين وغير المرتبطين وتحليلات العودة؛ الاختبارات المطلوبة تشمل الرحلة الكاملة والتزامن والإلغاء والاسترداد وتغيير الهاتف والصلاحيات ببيانات معزولة فقط.
- حالة الإضافة: مراجعة البنية وخطة توافق جارية؛ لم تُنفذ أو تُختبر بعد. لا نشر ولا تغيير إنتاج.
