## Exact private issuing contract

`prepare_offline_reward_issue(request, preparation, consent, registration, staff UUID[])` requires the actual current owner who originally prepared the accepted-22019 hold witness and proposed the accepted-23736 financial benefit. It uses the applied-25939 live checker without impersonating the actual customer, synchronizes actual typed debt, and requires debt clear. The backing command freezes full financial/worker snapshots. A differently bound payload on the same request is rejected. Closed unknown requests stay closed before any producer can create a job.

`place_offline_reward_issue(request)` serializes the same request and independently rechecks actual customer session/link/email/contact/consent/withdrawal, original quote/hold/source-refund/expiry, typed debt and unchanged real dispatch/HR financial snapshot. It repeats financial authorization after fact-lock waits. It creates an actual received **Walk-in** order, exactly one gross service line, typed profile/car sidecar, frozen worker commission lines and reception row. `customer_id` and `booking_id` stay NULL: no dummy Auth or fake appointment. The new canonical invoice has `total=0`, `discount=gross`, `payment_method=reward_coverage`, actual numbered invoice/work reference and existing QR/document stamping. It never converts an old cash invoice or writes any cash/card/payment event.

A same-transaction consume event links actual authorization transaction ID, exact consent/proposal, owner/profile, order/invoice and typed redemption. Only then can the old reserve claims be append-released and the SAME earning IDs receive new reward claims under the existing **one active claim per earning** unique index. The reservation becomes consumed; history cannot reopen. Actual receipt/claims/cover event exist before final invoice INSERT so the existing AFTER INSERT immutable document sees covered status immediately. Deferred guards require final real invoice/order/claims/consent/sidecar/command coherence at commit; enum admission alone cannot commit partial consumption. Invoice admission also checks actual expiry at insertion.

`get_offline_reward_issue(request)` returns exact own canonical payload/receipt with live work/invoice/payment status overlay; absent is nondefinitive. It checks the actual operator before cached responses. `close_offline_reward_issue(request)` fences an unknown nonce permanently; known unissued preparation closes its backing command and audited unconsumed hold, while issued requests return the existing receipt. `ack_offline_reward_issue` acknowledges only an actual terminal own request and exact backing slot. ## Cancellation and actual consumed-source refunds

`cancel_offline_reward_issue(nonce, issue, reason)` is private current-owner management action. It derives the original actual financial subject even if its link is revoked, takes identity then reward/source locks, and delegates existing received-only cancellation. The same-transaction synchronizer appends immutable restore or forfeit witness according to the **selected frozen quote rule**. Restore releases actual reward and debt-offset claims and closes related reviews without resetting earning terms/expiry; forfeit preserves spent claims. No credit is minted. Original covered document/QR stays unchanged; live coverage becomes cancelled reward. Deferred invoice coherence prevents a bare public normal cancellation from committing an unsynchronized reward receipt.

`sync_offline_profile_rewards(profile)` reuses canonical credit/claim/redemption/review tables and actual `reward_credit_refund`, not a second ledger/queue. Before each new reservation and issue, it observes actual full refund even before async reversal and creates one review per original consumed claim/refund ID. The issued benefit is honored; no retroactive customer charge. Offset consumes only a genuine valid unclaimed same-offer/branch credit whose actual completion-and-cash-sale qualification occurs after the actual refund, under sorted invoice locks and fresh refund/expiry reread. The causal watermark is the maximum of canonical completed-work ledger/physical-span completion clock and actual cash-sale outbox append clock, compared with the exact refund outbox append clock. Neither async canonical-earning insertion time nor transaction-start payment now() can turn an older visit into a future one. Missing durable actual-fact proof fails closed; the existing outbox is read, never replaced or mutated by this kernel. Freeze blocks new spend until explicit owner acknowledgment; acknowledgment does not waive debt or mint credit, and then the same actual future-credit offset is required. A later refund of an allocated offset removes its debt-paying effect and requires another genuine offset. Original expiry is never rewritten.

`list_offline_reward_refund_reviews(profile)` and `resolve_offline_reward_refund_review(nonce, review, note)` are private current-owner audit actions. The resolver uses exact immutable command receipts and current typed synchronization, with no cross-owner credit transfer. New reservation releases only actually expired/refunded UNCONSUMED holds before debt synchronization so stale holds cannot permanently prevent real repayment. Consumed reservations cannot be released through the old unconsumed API.
